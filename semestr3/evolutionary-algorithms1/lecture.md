## Introduction

- population-based stochastic search
- two principles: variation + selection
- population of solutions, not just one solution
	- opposed to NNs – gradient descent maintains only one solution
- search … finding a candidate satisfying some requirements
- optimization … we have some objective function $f(x)$
- learning … use observations to improve future decisions
- black-box optimization
	- we only need to tell good and bad solutions apart
	- we don't need to know the structure of $f(x)$, it can be very general
- “searching without knowing where to go”
- example: airfoil (wing profile) optimization
- in the second semester, we'll discuss how the search algorithms can adapt (learn)
- Charles Darwin
	- theory of natural selection
	- there are some hereditary traits, there is some variation
	- × Lamarck theory
		- individuals improve in their lifetime
		- faster convergence, higher risk of getting stuck in local optima
- Gregor Mendel
	- experiments on plant hybridization
	- “we're not mixing, we're transferring discrete units of information”
- genes
	- human genome has 0.8 GB (fits on a CD)
- genotype vs. fenotype
	- variation works on the genotype
	- evaluation is performed on the fenotype
- diploidy … organisms often carry two chromosome sets (one from each parent)
	- there's no good implementation in evolutionary algorithms yet
- evolutionary cycle
	- current population $P_t$
	- parent selection
	- variation – generates new candidates
	- evaluation
	- survivor selection
	- next population $P_{t+1}$
- notation
	- $\mu$ … number of individuals in a population
	- $\lambda$ … number of offspring
- objective value is not always the fitness
- selection pressure
	- how strongly the differences in fitness affect the parent selection
	- “does everyone mate with the best individual?”
- who survives?
	- do we kill the parents?
	- generational replacement × overlapping replacement
	- elitist replacement – we keep the best-so-far solution
- composition of the population serves as the memory of the search
	- it may be useful to keep it diverse
- the step from one to the next generation is stochastic
- genetic drift
	- some change in the population may be caused just by the stochasticity of the process (not by the differences in fitness)
	- because of the finite sampling (we don't have infinitely many individuals)
- how to represent the genotype (and how to mutate/combine)
	- bit string → flip bits
	- real vector → perturb coordinates
	- permutation → swap/reorder
	- tree / program → change structure
- representation affects how the neighborhood looks like
	- standard binary vs. Gray code
	- in standard binary encoding, a single bit flip may easily change the order of the number (for Gray code, it does not happen that easily)
- computational cost
- when is evolution attractive?
	- awkward search space
	- black-box evaluation
	- we want more than one optimum
- sometimes, we can combine evolution with other approaches

## Genetic Algorithms

- simple genetic algorithm
	- representation: fixed-length bit string
	- variation: one-point crossover + bit mutation
	- survivor selection: generational replacement (we kill the parents)
- John Holland
	- studied the adaptation in natural and artificial systems
	- introduced the simple genetic algorithm
- chromosome
	- locus … position $i$ in the chromosome
	- allele … the value $x_i\in\set{0,1}$ at that locus
	- chromosome/genotype … the complete string
- selection
	- roulette-wheel selection
	- in the real-world problems, we may need to somehow transform the objective value to get a useful fitness function
	- we can use ranking-based selection
		- tournament selection
- uniform crossover
	- does it make sense?
	- is there any linkage between alleles? → we should use one-point crossover
- schema theory
	- it's been over-dramatized :)
	- schema describes a family of strings
	- important: *to evaluate a fitness of a schema, we only consider only the individuals in the population*
	- schema → building blocks
	- schema theorem does not prove that…
		- a GA converges to the global optimum
		- useful building blocks exist
		- crossover is generally superior to mutation
- two test problems
	- OneMax
	- OneMax with 4-bit traps
		- this problem is more difficult
		- you can solve the traps individually
- quality and diversity of the population
- forces
	- selection – increases the quality (sampling is focused on better individuals), reduces the diversity
	- variation – proposes new candidates; may improve or worsen the quality, increases the diveristy
	- draft – the process is stochastic so there are some traits propagating through the popoulation even if they provide no evolutionary benefit; has no systematic effect on the quality of the population, but slowly reduces the diversity
- selection pressure
	- selection intensity
	- takeover time
		- can be studied if we have a selection-only algorithm
		- for tournament selection, using higher $k$ means higher selection pressure (we are choosing the maximum from more individuals → worse individuals are much less likely to get selected)
- elitims vs. just storing the best individual
	- we always want to save the best individual to be able to return it from the algorithm
	- elitims makes this individual part of the next population
- selection pressure is a tradeoff between speed and diversity
- (1+1) evolutionary algorithm = hill climbing
	- we can derive what is a good probability of mutation
	- it's $1/\ell$
	- (we don't have to remember the theorem)
- population size is connected to the number of generations
	- we may have a fixed evaluation budget (evaluations take time) → the more generations we want to have, the smaller population we can have (and vice versa)
- with a large population, we can use *island model* and parallelize the computation
- for more difficult problems, we may need a larger population (it allows for better exploration)
- hitchhiking
	- a suboptimal trait survives because it happens to be a part of an individual with high fitness
	- mutation helps to prevent this
- how to measure diversity
	- on the genotypic level – using Hamming distance etc.
	- on the phenotypic level – how different are the decoded individuals / how different is their behavior (may be hard to measure)
	- using fitness – e.g. standard deviation
- no free lunch
	- averaged over all possible objective functions on a finite space, every black-box search algorithm performs equally well
	- but we don't care about all problems! we are interested in one particular class of problems
- questions
	- what are we learning in EA? the structure of the population
	- representation matters
	- can a perfect individual live in a bad population? yes, bad population is useful for exploration

## Representation and Constraints

- two approaches
	1. encode everything as bits, keep the operators from SGA
		- Holland's approach
	2. keep the type, change the operators
- unary representation
	- we count the number of ones in the binary sequence
	- there are many different genotypes coresponding to one fenotype
	- non-uniform redundancy creates bias
- integer operators (we consider numbers from a finite range)
	- random reset (unbiased mutation) – replace the value by a random value of the range
	- creep (biased mutation) – add a small random step
	- crossover – we can perform a one-point crossover on vectors of integers
	- *important question: is there an ordering between the values?*
- mutation of real numbers
	- uniform – generate a new random value from $[a,b]$
	- Gaussian – add a value from $\mathcal N(0,\sigma^2)$
	- non-uniform – simulated annealing
- crossover of real vectors
	- simple one-point (or even uniform) crossover behaves in a dicrete way
	- an idea offspring may lie somewhere between the parents
		- arithmetic crossover: $\alpha F+(1-\alpha)M$
	- we may consider the entire box of the parents (also widened a bit) → blend (BLX-$\alpha$)
	- we may sample around the discrete points → simulated binary (SBX)
- combining more than two parents
	- uniform crossover (may be even weighted according to fitness)
	- diagonal crossover
	- arithmetic crossover
- mixed variables
